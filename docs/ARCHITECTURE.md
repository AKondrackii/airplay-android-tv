# Технический отчёт и архитектура

## 1. Исследование: можно ли сделать полноценный AirPlay-приёмник на Android TV

### Протокол AirPlay
- **Обнаружение:** Bonjour/mDNS, сервисы `_airplay._tcp` (видео и зеркалирование) и `_raop._tcp` (аудио).
  В TXT-записях передаются флаги возможностей (`features`), модель, публичный ключ и признак пароля.
- **Управление:** RTSP/1.0 (зеркалирование и аудио) и HTTP/1.1 (AirPlay-видео) на одном TCP-порту.
- **Сопряжение:** `pair-setup`/`pair-verify` (Ed25519 + X25519 + AES), а также legacy-сопряжение по PIN (SRP-6a).
- **FairPlay SAP:** обязательное «рукопожатие» FairPlay (`fp-setup`), без которого iOS не отправит ключ потока.
  Открытая реализация — `playfair`: результат реверс-инжиниринга, лицензия GPL-3.0.
- **Потоки:** зеркалирование идёт в H.264 (или H.265) по отдельному TCP-соединению и шифруется AES-CTR.
  Аудио идёт по RTP/UDP: AAC-ELD при зеркалировании, ALAC или AAC-LC для музыки. Синхронизация через NTP.
- **AirPlay-видео (URL):** отправитель передаёт ссылку. Это либо прямой http(s)-адрес (Safari),
  либо HLS-плейлист, который приёмник запрашивает у iPhone обратными запросами (FCUP), как в YouTube.

### Open-source реализации: проверка
| Проект | Что умеет | Лицензия | Пригодность для Android |
|---|---|---|---|
| **UxPlay** (FDH2/UxPlay, Linux/macOS/Windows) | Зеркалирование iOS/iPadOS/macOS (протокол AirPlay 2 mirroring), AirPlay-аудио ALAC/AAC, HLS-видео, PIN и пароль, H.265 | GPL-3.0 (код RPiPlay/dsafa22/Juho Vähä-Herttua — LGPL-2.1) | **Выбран.** Протокольная библиотека `lib/` написана на чистом C. Её зависимости: OpenSSL, libplist, llhttp. Рендеринг на GStreamer заменяется своим. |
| RPiPlay | Предшественник UxPlay, только Raspberry Pi | GPL-3.0 | Устарел: всё полезное вошло в UxPlay. |
| Shairport Sync | Только аудио, в том числе AirPlay 2 multi-room (PTP) | MIT/BSD с GPL-частями | Требует демона NQPTP и Linux-окружения. Для Android нецелесообразен. Мультирум в этот выпуск не входит. |
| dsafa22/AirplayServer | Старый Android-порт зеркалирования | GPL | Заброшен, не поддерживает актуальные iOS. |

**Итог:** протокольное ядро берём из UxPlay (собирается через NDK). Всё, что в UxPlay зависит от Linux,
пишем заново под Android: mDNS, рендеринг, аудио, жизненный цикл, безопасность и UI.

### Что реально достижимо (честная матрица совместимости)
| Сценарий | Статус | Комментарий |
|---|---|---|
| Повтор экрана iPhone/iPad | ✅ Реализован | Протокол UxPlay, H.264 через MediaCodec, звук AAC-ELD |
| Повтор/расширение экрана Mac | ✅ Реализован | macOS использует тот же протокол |
| H.265 при повторе экрана | ✅ Если есть аппаратный HEVC | Включается автоматически |
| Музыка и звук (Apple Music, подкасты, системный звук) | ✅ Реализован | ALAC (декодер Apple), AAC-LC/ELD; обложка, метаданные, прогресс |
| AirPlay-видео из YouTube и других HLS-приложений | ✅ Реализован | Через HLS-прокси UxPlay и Media3 ExoPlayer |
| AirPlay-видео по прямой ссылке (Safari) | ✅ Реализован | Media3 |
| Видео с DRM (Netflix, Apple TV+, Disney+) | ❌ Невозможно | Нужен FairPlay Streaming, для сторонних устройств он закрыт. При повторе экрана iOS показывает чёрный кадр на защищённом контенте. |
| AirPlay 2 multi-room, группировка с HomePod, буферизированное аудио, PTP | ❌ Не реализовано | Нужна HomeKit-сопряжение и протокол Apple, открытой рабочей реализации под Android нет. Телевизор не добавляется в приложение «Дом». |
| Выбор громкости с iPhone | ✅ | Можно отключить в настройках |
| Работа при выключенном экране ТВ | ⚠️ Зависит от прошивки | Большинство ТВ в режиме ожидания отключают Wi-Fi и усыпляют CPU. Обойти это нельзя. |

**Терминология:** «AirPlay 2» в интерфейсе не используется. Приложение поддерживает **протокол зеркалирования
и аудио AirPlay** (в том числе современный вариант с pair-verify, которым пользуются iOS 15–18+),
но не AirPlay 2 multi-room или буферизированное аудио.

### Ограничения Android TV
- **Фоновый запуск активити:** с Android 10 приложение не может само вывести экран поверх другого
  приложения без разрешения «Поверх других приложений» (SYSTEM_ALERT_WINDOW). Если разрешения нет,
  звук продолжает играть в фоне, видео декодируется вхолостую, а пользователь получает уведомление.
  На многих ТВ этот пункт настроек скрыт; есть adb-команда (см. README).
- **Foreground Service:** с Android 14 обязателен тип. В режиме ожидания используется
  `connectedDevice`: Android 15 по-прежнему разрешает запускать его из `BOOT_COMPLETED`, а `mediaPlayback` — нет.
  Во время сессии добавляется `mediaPlayback`.
- **MAC-адрес** приложениям недоступен. Генерируется постоянный случайный «локально администрируемый» ID.
- **Doze** на ТВ почти не встречается, потому что устройство питается от сети. В режиме ожидания
  блокировки не держатся (экономия), а во время сессии берутся `PARTIAL_WAKE_LOCK` и Wi-Fi low-latency lock.
- **Автозапуск:** часть прошивок (Xiaomi, некоторые TCL) блокирует `BOOT_COMPLETED` для сторонних приложений.

## 2. Архитектура

```
┌──────────── app (UI, Compose) ─────────────┐   UI только наблюдает StateFlow
│ MainActivity: Home / Settings / Log / Player│   и одалживает Surface плееру
└───────────────▲─────────────────────────────┘
                │ StateFlow
┌───────────────┴──────── ReceiverService (Foreground) ───────────────────┐
│ ReceiverController: settings + network → (пере)запуск приёмника и mDNS   │
│                                                                          │
│  network ──────────┐   security ─────────────┐   playback ─────────────┐ │
│  NetworkMonitor    │   SubnetFilter          │   MirrorVideoDecoder     │ │
│  MdnsAdvertiser    │   RateLimiter           │   AudioEngine (AAC/PCM)  │ │
│  (JmDNS на одном   │   ReceiverPolicy        │   HlsVideoPlayer (Media3)│ │
│   интерфейсе)      │   SecretStore/Trusted   │   PlaybackEngine=MediaSink│ │
│                    │      ▲ ConnectionPolicy │        ▲ MediaSink       │ │
│                    │      │                  │        │                 │ │
│  airplay ──────────┴──────┴──────────────────┴────────┴───────────────┐ │
│  AirPlayReceiver (Kotlin) ⇄ JNI ⇄ libairplaytv.so                      │ │
│     UxPlay lib (RTSP/HTTP, pairing, FairPlay SAP, RTP, mirror, HLS)    │ │
│     + libplist + OpenSSL 3.5 (static) + Apple ALAC + dnssd_android.c    │ │
└──────────────────────────────────────────────────────────────────────────┘
```

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `core` | Модели, `AppLog`, `SettingsRepository` (DataStore), интерфейсы `ConnectionPolicy` и `MediaSink` | — |
| `security` | Фильтр подсетей, rate limiting, подтверждение подключений, доверенные устройства, шифрование секретов (Keystore) | core |
| `network` | Отслеживание разрешённой сети (Wi-Fi/Ethernet, без VPN и мобильной сети), mDNS-анонс | core |
| `airplay` | NDK-сборка UxPlay, JNI-мост, Kotlin-обёртка `AirPlayReceiver` | core |
| `playback` | MediaCodec (видео и AAC), AudioTrack, Media3 HLS, парсеры NAL и DMAP | core |
| `app` | UI, Foreground Service, автозапуск, сборка графа зависимостей | все |

`airplay` не знает о `security` и `playback`: он работает через интерфейсы из `core`, а связывает их `AppGraph`.
DI-фреймворк не нужен, граф описан вручную примерно в 60 строках.

### Ключевые решения
1. **Ядро протокола — UxPlay через NDK, а не своя реализация.** Протокол закрыт и меняется с версиями iOS,
   а UxPlay активно сопровождается. Изменения в вендорном коде минимальны, помечены `AIRPLAYTV:` и перечислены в `THIRD_PARTY_NOTICES.md`.
2. **mDNS в Kotlin (JmDNS) с привязкой к IP разрешённого интерфейса.** TXT-записи формирует C-код
   (`dnssd_android.c`) теми же ключами, что и UxPlay. Это гарантирует одинаковые данные в анонсе и в `/info`.
3. **Фильтр сети стоит до разбора протокола:** хук `airplaytv_accept_filter` вызывается сразу после `accept()`.
4. **Декодер живёт в сервисе.** Плеер только подключает Surface (`setOutputSurface`). Если экран не виден,
   декодер работает на скрытой поверхности без отрисовки, поэтому при открытии плеера не нужен новый ключевой кадр.
5. **Без копирования памяти через JNI:** кадры передаются как `DirectByteBuffer`, указывающий на нативный буфер,
   и сразу копируются во входной буфер MediaCodec. GC не нагружается.
6. **ALAC декодируется в нативном коде** (референсный декодер Apple), потому что `audio/alac` в MediaCodec есть только с Android 12+.
7. **OpenSSL 3.5 LTS собирается из исходников** с проверкой SHA-256 (`scripts/build-openssl-android.sh`),
   статически, без лишних модулей.

## 3. Риски и сложные места
| Риск | Влияние | Меры |
|---|---|---|
| Apple меняет протокол в новой iOS | Высокое | Ядро UxPlay обновляется заменой `third_party/uxplay` (см. `UPSTREAM`) |
| Правовой статус FairPlay-рукопожатия (`playfair`, реверс-инжиниринг) и товарного знака AirPlay | Среднее | Приложение под GPL-3.0, исходники открыты. Перед публикацией в Google Play нужна юридическая проверка названия. |
| Слабые декодеры дешёвых приставок | Среднее | Настройки 720p/30 к/с, аппаратное декодирование, малая задержка |
| Блокировка автозапуска и фоновой работы прошивкой | Среднее | Описано в README; сервис перезапускается (`START_STICKY`) |
| Ошибки в C-коде при враждебном вводе | Высокое | Фильтр до разбора, rate limiting, фаззинг (нашёл и исправил 4 падения UxPlay и 1 уязвимость с PIN-окном), `assert` включены в release |
| Задержка A/V при зеркалировании | Низкое | Видео и звук отрисовываются сразу, без буферизации |
